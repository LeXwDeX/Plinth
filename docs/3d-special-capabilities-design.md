# 3D 特殊能力、输入互通与右侧工具区方案

设计基线：2026-09-30。本文保留候选能力与架构设计，不声明当前实现或部署状态。实施规格、依赖、进度与验收统一见 3D 能力扩展里程碑（Milestone #2）。

用户要求先找全特殊功能和本地上传边界，再设计格式转换兜底、特殊能力接入及 3D 右侧功能区。范围为项目当前三家 3D 供应商 Meshy、Tripo、Hyper3D 的公开 3D 生成/处理 API，以及与这些 API 容易混淆的官网工具。供应商内部、未公开或企业洽谈中的接口不能按公开契约登记为可执行功能。

## 1. 调研入口与证据层次

- [Meshy / Tripo 逐端点调研](3d-special-capabilities-meshy-tripo-research.md)：独立处理、上传、导入、打印、创作模板及输入限制。
- [Hyper3D 逐端点调研](3d-special-capabilities-hyper3d-research.md)：Rodin、Agentic、Bang、Texture、ChatAvatar、WorldGen、OmniCraft 和客户专属 ControlNet。
- 官方目录：[Meshy API](https://docs.meshy.ai/en/api)、[Tripo v3](https://developers.tripo3d.ai/en/docs/introduction)、[Hyper3D API](https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5)。费用、开放条件和模型版本需在接入时再次核对。

## 2. 本地上传与内部任务 ID 的区别

| 供应商 | 外部本地模型可用的传输方式 | 内部任务关系的限制 | 接入策略 |
|---|---|---|---|
| Meshy | 若目标接口支持，服务端把本地资产字节编码为 JSON `model_url` 的 Data URI；也支持供应商能访问的 HTTPS 模型 URL。不是统一 multipart 模型上传接口 | Convert 与 Remesh / Retexture 的任务类型范围不同；Animation 要求真实 Rigging task，不能用上传文件或任意生成 ID 代替 | 优先复用合法原生依赖；否则按具体接口的外部模型契约传字节，避免要求供应商访问内网地址 |
| Tripo v3 | `POST /files` multipart 或 presign 上传得到 `file_token`；多个处理端点可接受 token、URL 或 task；另有 `models/import` | Complete 要求 Segment task；Retarget 要求 Rigged task。导入后得到 task 也不自动具备所有语义前置条件 | 私有上传/导入检查点、token 只留服务端；具体端点须逐项验证输入类型、来源 task 类型和收费 |
| Hyper3D | Bang 上传 `model`；Texture 上传 `model` + `image`；Rodin / Agentic 上传参考图 | Bang 的 `asset_id` 指 Rodin 已完成生成响应的顶层 UUID；其他供应商的 ID 不能使用 | 跨供应商走本地 READY 字节的 multipart；ChatAvatar / WorldGen 尚无本轮可确认的公开调用契约 |

结论：不能以“有没有内部 Task ID”判断整个供应商是否支持外部文件。文件能被接收、能被转换、能被绑定、能被动画接口消费，是四个不同条件。所有客户端选择都只引用平台 Task / Asset ID，不让用户输入或看到上游私有 ID。

## 3. 能力分类与接入边界

| 能力组 | 公开 API 能力线索与候选 | 仍需单独处理的边界 |
|---|---|---|
| 特殊生成 / 参考图准备 | Rodin Agentic；Meshy 多视图、Creative Lab 模板；Tripo H/P 多视图、Image / Edit Multiview、Image-to-Splat（单图文件 token / URL 输入，独立 `.splat` 产物） | 生成参数不一定是独立 API；多视图图像编辑不等于网格编辑；模板和多对象场景不等价；3DGS 不作为普通 Mesh 呈现 |
| 网格 / 材质 | Meshy Remesh、Retexture、UV Unwrap；Tripo Decimate、Texture、Segment、Smart Segmentation、Complete、P2 Mesh Local Edit、Refine / Stylize（后两项路由已证，详细契约待补）；Hyper3D Bang、Texture | 普通分割、Smart Segmentation 自动建模、P2 bbox 局部精修是不同合同；不能把 Bang 或补全宣称为任意局部几何替换；P2 编辑也不等于任意笔刷雕刻 |
| 骨骼 / 动作 | Meshy Rigging、Animation、Text-to-Motion；Tripo Rig Check、Rig、Retarget | 外部角色输入限制不同；绑定后的原生 task 关系不可由文件转换伪造；Motion clip 与角色模型分开 |
| 格式 / 尺寸 / 打印 | Meshy Convert、Resize、打印工具；Tripo Convert | 纯转换使用独立 Convert API，不能借 Remesh 默默改变网格；打印报告不作为模型资产 |
| Hyper3D 脸模 / 完整世界 / 网页局部编辑 | 官网 ChatAvatar、WorldGen、Partial Edit 产品已证实 | 本轮未找到这三项的公开请求/响应、上传、费用与权限契约，保持接入待补证；不猜端点或冒充 Rodin 参数。Tripo P2 局部网格编辑另见上表，不能与此处未证状态混用 |
| 浏览器本地工具 / 客户专属功能 | OmniCraft Mesh Editor、Converter 等网页工具；特定客户 ControlNet | 网页存在不证明公开服务 API。OmniCraft Editor 明确本机运行；Voxel / Point Cloud 客户专属文档不等于标准 cloud API |

完整功能和限制以两份逐端点调研表为准；本表是接入分类，未声明其全部已经注册或运行。

## 5. 格式兜底策略

仅在已接线且验证通过的候选之间，按顺序提出可执行路径；未实施的本地转换不能阻挡已可用的其他路线。预览路径不触发上游调用：

1. **复用已有表示**：当前同 owner 模型若已有满足目标输入契约的 READY 格式，直接使用对应 Asset，无须新任务。
2. **有界本地转换**：规划先评估 GLB / glTF 容器转换与依赖内嵌；只有实际实现和特征验收通过的组合才注册。不得承诺任意 FBX / BLEND / USDZ / 骨骼动画无损互转。
3. **供应商纯转换**：已有公开契约的 Meshy Convert、Tripo Convert 作为显式候选。向用户说明目标服务、预计费用、保留/丢失特征，再批准这一冻结步骤。
4. **真实前置处理**：格式满足但缺少骨骼、部件关系、UV 或原生任务资格时，分别提出 Rigging / Segment 等步骤；不能以改扩展名或导入 task 代替。
5. **明确不可用**：没有可证明路径、账号未接线或输出表示不匹配时，保留原因和可选路径；不静默替换用户所选模型、不盲目重发付费请求。

“兜底”是可解释的方案选择，不是暗中增加费用或破坏模型。现有模型始终保留，转换/处理产生新版本和真实 Asset。目标步骤再冻结该产物，每步独立取得 ExecutionGrant，仅会话策略要求时请求人工决定。

| 目标表示 | 必须说明的特征边界 |
|---|---|
| GLB / glTF | 原格式可携带材质、UV、骨骼、动画，但转换器必须分别证明保留；glTF 外部依赖须完整内嵌或受控打包 |
| OBJ / STL | OBJ 不承载原生骨骼动画；STL 主要是几何，不能当作完整材质/骨骼/动画包 |
| 3MF | 打印表示及颜色/组件不等于实时角色骨骼和动作，依赖具体输出合同 |
| FBX / USDZ / BLEND | 支持范围取决于实际转换器，不能因扩展名可导出就宣称全特征保留 |
| Gaussian Splat | 与 Mesh 是不同表示；不存在本轮已证明的常规格式互转路径，需专用渲染和重建能力 |

本地转换仍通过 Generation 的本地 Port 成为公开转换 Task。Provider 为完成某个公开步骤所需的上传/导入留在 Adapter 私有检查点，可能计费的子作业必须在执行前纳入该步骤授权。运行镜像保持现有 Go 单进程边界，未经方案变更不引入 Blender / Assimp CLI 或其他驻留服务。

## 6. 服务端判断与 Schema

沿已有 `parameters`、`same_provider`、`task_capabilities`、格式和大小约束扩展：

- 来源：`task_asset` / `input_asset` 联合引用，均为当前 owner 的平台 Asset；有真实 Task 时才附平台 Task。
- 输入替代组：任务与文件二选一、多参考图和其他依赖的精确关系。
- 内容约束：模型格式、大小、纹理、骨骼、UV、部件、角色类型及原生来源；不能只靠 MIME 或 Provider 名称判断。
- 目标与损失：转换路径、目标格式、保留特征、已知丢失、前置步骤与成本。
- 工具元数据：模型专属 / 通用分组、创建 / 当前模型处理语义、排序、标签、控件和原因文案。
- 输出类型：单模型、多部件、motion clip、打印报告、3DGS、scene package 分别声明角色和呈现契约。
- 私有 upload / import / dispatch 端点及检查点仅留服务端，公开投影不包含运行配置和上游标识。

拟扩展资产适用工具投影，返回 Offering 与适用性：可直接执行、需转换、需前置步骤、不可用。它们是工具适用性，不是公开 Task 状态。PrepareInput 再校验 owner、来源、Offering revision 并冻结实际字节，不信任旧视图；用户批准后，SubmitPrepared 校验绑定该冻结输入的 ExecutionGrant，再接受公开 Task。

## 7. 3D 右侧功能区

桌面为可收起侧栏，保留主视口和左侧可收起 Agent 浮层；整体任务进度仍在顶栏。窄屏用可关闭抽屉，避免同时展开多个面板遮住模型。

桌面工作区为左 / 中 / 右三栏：左侧是 Agent 对话及其下方的模型选择；中间是主画布；右侧是功能面板。窄屏按 Agent、模型选择、画布、功能面板顺序纵向排列，避免同时展开多个面板遮住模型。任务进度仍在顶栏。画布下方放选择、平移、缩放、绘图等基础操作。

右侧从上到下：

1. **通用功能**：按功能语义和跨来源用途归类，不要求机械地存在于所有供应商 API。格式转换即使当前只有一家供应商可执行，也仍是通用功能；执行前明确选择满足目标格式合同的 Offering，不静默切换用户选定的生成模型。重纹理、减面、导出及具有共同语义的 Rigging 也可列为通用功能；Rigging 的物种选项差异不改变功能归类。
2. **模型差异化功能**：由 Schema 声明的模型专用生成模式或产品流程，随左侧所选模型改变，例如 Creative Lab、Smart Segmentation 图像自动分部建模、Rodin Avatar / World 及专用动作生成。不要把供应商实现方等同于用户功能分组：分割、UV 展开、打印拆分、局部精修若按通用操作语义接受本地或他家来源，也属于通用功能，即使当前只有一个 Tripo 或 Meshy Offering 可执行。该 Offering 的私有参数放在所选操作详情；不因更换左侧生成模型而隐藏通用功能。内部区分“新建资产”和“处理当前模型”；ChatAvatar / WorldGen 属于新建资产，不是任意现有 Mesh 的编辑按钮。
3. **当前模型 / 输入与操作详情**：呈现当前输入资产、来源、版本和格式；选择已有资产或上传本地文件。选择功能后展示参数、来源、产物说明、成本和逐步同意；失败时保留成功步骤，只恢复失败或暂停步骤。上传文件是合法输入，不声称已经生成成功。

画布底部的选择、平移、缩放、绘图等是基础编辑工具，与右侧模型功能分开。功能选择只更新 Harness 选择并让 Agent 可读的摘要同步显示；它本身不执行工具、不创建 Task，也不构成付费同意。

未接入项目只显示产品可理解的“暂不可用”及原因，不在用户界面显示 API 路径、私有 ID、上游 URL 或调试 JSON。界面里的“当前模型特有”和“通用”是用户分组，底层仍是同一 Catalog / Generation / Asset 契约。

## 11. 通用与差异化功能统一接入 Harness

本节响应用户后续方向：先完善通用与差异化功能；右侧选择属于 Harness，通过提示词注入和动态工具注册送给 Agent。本节是设计契约；实现与验收见 #181。

### 11.1 同一份选择驱动三个入口

通用/差异化是界面分组；每项可执行功能仍由 Catalog 声明 Capability、Offering、输入输出、参数、费用与工具接线。Harness 保存用户本次选择，并在每轮 Agent 开始时由服务端解析为同一份有效快照：

```text
Catalog + 当前运行可用性 + 用户选择 + 已拥有的输入资产
  → 服务端解析有效 Harness 快照
  → 同时产生：结构化上下文、动态工具定义、工具执行约束
  → Agent 提出具体操作 → Generation 冻结输入 → 按会话策略逐步取得 ExecutionGrant → 提交 Task
```

“必然知道”可验收为每轮模型请求确实携带所选功能和对应工具；不能把模型一定理解、一定调用或一定成功当作确定性承诺。模型偏离选择时，服务端拒绝不匹配的新操作，返回可纠正原因；没有合法路径则解释缺口，不静默替换。

### 11.2 Harness 保存什么

下列是拟议的语义字段，具体名称在 Schema 设计阶段确定，不表示已有 API：

| 内容 | 语义 |
|---|---|
| 会话与选择修订 | session ID、Harness revision；用于刷新恢复、并发更新和每轮快照身份 |
| 当前选定操作 | Capability、具体 Offering 及其修订；区分“用户要求当前做什么”和“哪些工具允许使用” |
| 启用的工具范围 | 用户启用的通用/差异化功能集合；服务端与已接线、账号可用及输入条件求交集 |
| 输入与作用范围 | 平台 Asset 引用、确有来源时的平台 Task、当前版本；局部处理附目标对象与有效 bbox/mask 等输入 |
| 用户固定参数 | 明确固定的参数、格式和操作目标；Agent 建议不能覆盖这些值，除非用户修改选择 |
| 允许的补充与前置路径 | Agent 可补全的参数范围，以及是否允许提出转换/绑定/分割方案；允许提出方案不等于允许付费执行 |

创建新资产的工具可以没有当前模型来源；处理现有模型的工具必须满足相应来源契约。不能为新建类工具伪造输入模型，也不能为本地上传伪造成功 Task。

### 11.3 提示词注入与动态工具注册

- **上下文注入**：每轮明确给出用户选定操作、Offering、输入资产/版本、固定参数、可补全参数、有效工具与前置条件。由服务端将规范化字段按 Schema 模板组织；用户自由文本作为数据，不能变成额外工具权限。客户端不提交可执行权限或 Provider 私有标识。
- **动态工具定义**：从 Schema 已声明且有执行器的工具中选出本轮有效集合，并投影当前 Offering 的参数合同。生成参数变化复用现有生成工具；独立特殊操作按其合同登记工具。动态注册是选择和实例化已接线工具，不能凭提示词创建不存在的执行器。
- **执行约束**：展示给模型的工具和实际可调用工具使用同一快照与解析策略。后端再检查用户固定的操作、Offering、来源、owner、参数与修订；不能只隐藏未启用工具而仍接受它们的调用。
- **前置工具**：观察任务、查询能力、解释不可用原因等基础工具按必要范围保留。需转换/绑定/分割时允许产生前置方案；这些步骤通过明确的计划关系引用原目标，不能借前置步骤绕过用户固定的目标或未经同意收费。

当前 `internal/chat/tool_registry.go` 已从 Chat Schema 编译生成/Agent 工具，并对描述与执行使用统一的 domain/capability 过滤规则；这可作为扩展入口。本次核对没有证明已经实现按所选专属功能和资产条件的 Harness 动态注册，不能将它写为现有完成能力。

### 11.4 选择变更、授权与界面反馈

每轮快照固定，后续用户更改影响下一轮；若当前轮还要发起新操作，须比较最新选择修订，发现变化则暂停并重新解析。已经提交的公开 Task 继续按原冻结输入与授权观察，不因切换面板重复提交或撤销。尚未提交的待决同意与旧 PreparedInput 不得套用到新选择，须重新准备并确认。

右侧先显示“通用功能”，再显示随左侧模型选择变化的“差异化功能”，并呈现当前选定操作、已启用工具、来源和必要参数。通用性按功能语义和可接受输入来源判断，不以供应商 API 交集或当前执行供应商为标准：转换格式、分割、局部精修、UV 展开等若合同允许处理本地或他家来源，仍是通用功能，即使当前只有 Tripo 或 Meshy Offering 能执行；操作详情明确显示承接 Offering 与其参数，不因切换生成模型隐藏功能，也不能静默改动用户选定的生成模型。Rigging 的物种参数虽有差异，仍保持通用功能语义。差异化区承载 Schema 声明的模型专用生成模式或产品流程，如 Creative Lab、Smart Segmentation 图像自动分部建模、Rodin Avatar / World 和专用动作生成。Agent 区显示用户可读的“本轮使用……”摘要；原型中的同步只表示设计预览，未接 Harness 运行链。用户的新选择尚未进入当前轮时明示生效时机。来源切换后重新计算适用性，失效选择保持可解释状态，不能自动换成另一个操作。画布底部始终提供选择、平移、缩放和绘图等基础操作，不纳入模型差异化功能。

“已选择/已启用”“需前置步骤”“待同意”“正在执行”分别有真实依据。点击选择功能不提交任务，选择、提示词注入和工具可见都不构成付费同意。未接线功能仍明确不可用，不向 Agent 注册可执行工具。

### 11.5. 核心约束

用户选定 A 后，模型请求携带 A 与合法工具；调用 B 或修改用户固定 Offering 被后端拒绝；A 缺输入时可说明或准备合法前置方案；改变 Harness 不重发历史付费 Task；无法接线的功能不出现在可执行工具集合中。逐步 ExecutionGrant 按当前会话批准策略取得，仅策略要求时请求人工决定。

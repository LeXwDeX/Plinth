# Plinth 工作台重新设计：方案

- 日期：2026-10-08
- 决定（Lex，10-08）：主布局采用"对话 + 舞台"。
- 平台：只做 PC。目标视口 1440×900，最小 1280×720，兼顾 1366×768 和 1920×1080。
- 依据：现有界面清单 `docs/design/frontend-inventory.md`（50 条怪异点）、产品规则 `docs/product.md`。
- 状态：方案草稿，原型确认后开发。
- 修订：按 UX 验证报告 `docs/design/ux-validation-prototype.md` 修改（涉及第 2、3、4、5、6、8、9 节，新增 4.4、4.5 和第 10 节）。

## 1. 设计原则

1. **一个当前对象。** 任何时刻，舞台只显示一个当前对象（一张图或一个模型）。对话、工具、批准都围绕它。
2. **不让用户切模式。** 去掉顶栏的"图片创作 / 3D 模型"标签。舞台按当前对象的类型自动显示 2D 编辑器或 3D 查看器。
3. **版本链是主线。** 每次生成都是链上的一个新版本。2D v1 → 3D v1 → 2D v2 → 3D v2 一直显示在底部。
4. **对话常驻，不遮挡。** 对话是固定的左栏，不是浮层，不盖住画布。
5. **不打断。** 批准、错误和进度显示在对话里和版本条上。除了删除和付费确认，不弹出阻塞对话框。
6. **动作就近。** 对一个对象能做的事，放在舞台顶部的动作条上，不藏在悬停菜单里。

## 2. 布局（1440×900）

| 区域 | 尺寸 | 行为 |
|---|---|---|
| 顶栏 | 高 48px | 会话名可点击改名；会话下拉含搜索、新建、删除。右侧：批准模式、本会话积分、任务中心、余额、用户菜单。 |

| 舞台头 | 高 48px | 当前对象名、版本号、句柄、来源。右侧是对象动作。 |
| 工具栏 | 宽 48px，竖排在舞台左侧 | 只在 2D 对象时显示。3D 对象时换成视图模式按钮。 |
| 舞台 | 剩余空间 | 2D：Konva 画布，当前图居中。3D：model-viewer。 |
| 检查器 | 宽 300px。默认收起 | 点舞台头动作或当前对象类型变化时自动展开。每人记住状态。内容随对象类型变化（见第 4 节）。 |
| 版本条 | 高 112px | 本会话的版本链。点一个版本，舞台就切到它。 |
| 聚焦模式 | 全局 | 一键隐藏两侧，只留舞台。按 Tab（或点舞台头的“聚焦”按钮）同时收起对话栏和检查器，只留舞台、工具栏和版本条；再按恢复。 |

最小视口 1280 时，舞台宽不少于 **780px**（1280 − 360 − 48 − 检查器收起 0 − 边线）。

## 3. 对话栏

- **顶部：设定摘要。** 一行折叠条"设定：赛博朋克女刺客，深蓝紫配色…"。点开可编辑，最多 2000 字。
- **消息。** 用户消息靠右，Agent 消息靠左，不用气泡框住长文本。
- **结果卡片。** Agent 生成的图或模型显示为卡片：
  - 多张候选并排显示（不是轮播），每张有"选用"。
  - 卡片按钮："在舞台打开"、"转 3D"（图）或"截图到 2D"（模型）、"下载"。**多张候选是一个组（一次出图的几张图算一个版本），"选用"随时可改，不随后续步骤禁用。**
  - 卡片角标显示句柄 @img5 和积分。
- **批准卡片。** 手工模式下，文生 3D、图生 3D、换贴图在对话里显示一张批准卡片：步骤、模型、输入图缩略图、积分、[批准] [拒绝]。不再弹出阻塞对话框。卡片显示该步骤供应商的当前余额；余额低于本步费用时，"批准"置灰并说明。卡片写明"等待批准 · 24 小时内有效"。待批准步骤由后端保存，默认 24 小时内有效，刷新页面后仍在列表里（后端支持见第 10 节）。过期后卡片变为"已过期"，按钮变为"重新发起"。切换批准模式不会批准已挂起的卡片。
- **进度。** 生成中的步骤在消息里显示进度条，同时在版本条显示占位版本。
- **失败。** 失败消息显示原因和按钮。余额不足类失败不显示[重试]，显示[换一个模型]（该能力有其他供应商时）和[联系管理员]。其他可重试的失败显示[重试]。
- **输入区。**
  - 上方是"当前对象"芯片（芯片：输入框上方的小标签）：`当前：@img5 ✕`。它跟随舞台的当前对象。点 ✕ 本轮不带上下文。芯片带 32px 缩略图和 2D/3D 角标。消息中手写的 @句柄与芯片不同时，芯片变灰并提示以手写为准。
  - 输入 `@` 弹出本会话资产列表（缩略图 + 句柄）。
  - 拖入或粘贴图片会成为附件芯片。
  - 下方一行：`2D 模型▾` `3D 模型▾` `Skill▾` 和发送按钮。两个模型分开选，Agent 跨 2D/3D 时各用各的。
  - Enter 发送，Shift+Enter 换行；输入法选字时不发送。
  - **参数按钮**：比例、尺寸、张数（1–10，默认 4）。选定后显示为芯片 `16:9 · 4 张`。费用随张数显示在发送按钮旁。Skill 的推荐尺寸自动填入。
  - **上传按钮**：回形针，打开文件选择。拖文件到对话栏或舞台时整块高亮。附件芯片带缩略图。
  - **蒙版芯片**：蒙版是在图上涂出的一块区域，局部重绘只重画这一块。舞台上有未发送蒙版时，输入框上方显示 `蒙版 · @img5 ✕`，随消息发送。
- **消息操作。** 每条消息下方常显小按钮（不只在悬停时）。只有最后一条用户消息显示"编辑后重发"；更早的显示"复制到输入框"。Agent 最后一条显示"重新生成"，并写明费用。删除收进"更多"菜单，并需要确认。

## 4. 舞台与检查器

### 4.1 2D 对象

- 舞台显示当前图。画布仍可放多个元素（参考图、文字、形状），但默认聚焦当前图。
- 左侧竖排工具栏：选择 V、平移 H、画笔 B、橡皮 E、蒙版 M、裁剪 K、文字 T、形状 R。工具栏底部：撤销 Ctrl+Z、重做 Ctrl+Shift+Z。
- 选中工具后，舞台出现一条**工具参数条**（笔刷大小、颜色、透明度），替代现在的弹出浮层。参数条浮在舞台上方 8px，半透明，不占画布高度。蒙版时右侧有"完成（Enter）"和"退出（Esc）"；当前 2D 模型不支持蒙版时显示提示和一键切换。
- 右下角：缩放 `− 100% +` 和"适应"。
- 舞台头动作：局部重绘（进入蒙版）、去背景、**变体**（基于当前图再出几张，输入框预填"基于 @imgN，"）、**三视图**（同一角色的正面、侧面、背面三张图，给建模用，流程见 4.5）、转 3D、发到对话、下载。画布有手绘图层时多一个"合并为新版本（0 积分）"。
- 检查器标签页：**详情**（提示词、模型、尺寸、积分、来源链接）、**图层**。
- **灯箱。** 灯箱是整屏放大看图的界面。双击舞台上的图或按 Space 进入；←/→ 翻同组候选或相邻版本；Esc 退出。灯箱内有"选用"和"下载"。

### 4.2 3D 对象

- 舞台是 3D 查看器，背景中性灰，带地面网格。
- 左侧竖排换成视图模式：贴图 / 白模（不显示贴图，只看形状）/ 线框（只看面的边线）/ UV（贴图在模型表面的展开方式，待接口支持，先置灰）。贴图视图下可切通道（底色、法线、粗糙度）；可关闭自动旋转。
- 右下角显示面数（模型由多少个三角面组成）、贴图尺寸、文件大小。**这些由前端解析 GLB 得出，需要替换现有 model-viewer；拿不到时显示"—"。**
- 舞台头动作：截图到 2D、换贴图、处理、下载。
- 检查器标签页：
  - **处理**：顶部显示该模型的处理链状态（重拓扑 → 绑骨 → 动画）。一次选一个，显示积分，[开始]。换贴图（形状不变，重生表面贴图）：提示词与风格图**二选一**，说明"整套贴图重生，不能只改局部"；手工模式下需批准。重拓扑（重新生成面，通常减面）、绑骨（给模型装骨架）、动画（用骨架做动作）：自动批准，按钮直接写"开始 · N 积分"。动画在没有绑骨版本时置灰。
  - **格式**：列表来自服务端格式清单，随版本类型变：绑骨只有 FBX/GLB；动画按动作列文件；不可用的格式写原因。每行有单独下载；[补齐格式 约 N 积分]自动批准；[下载 ZIP]。
  - **详情**：同 2D。

### 4.3 空状态

- 新会话：舞台中间显示三个起步卡片："从文字出图"、"上传参考图"、"从文字生成 3D"，以及示例提示词。点卡片会填好输入框，不直接扣费。起步卡下方显示默认参数芯片（1:1 · 4 张），点可改。

### 4.4 比较视图

舞台头"比较"动作把舞台分成 2 格或 4 格。每格从版本条拖入一个版本，或点格子从下拉选。2D：同步缩放平移，另有滑杆对比（一条可拖的竖线，左边显示一个版本，右边显示另一个版本）。3D：同步旋转。比较视图里每格有"设为当前"。Esc 退出。

### 4.5 三视图流程

2D 对象的舞台头"三视图"发起 `create_three_view`。对话里出现三视图卡片：正 / 侧 / 背三个槽位。第一张自动生成；后两张各有"继续生成（约 6 积分）"，手工和自动模式都按 2D 规则自动批准。三张齐后合成组版本 `2D vN · 三视图`。转 3D 时只用正面那张，批准卡片的输入图标"正面"。（后端支持见第 10 节。）

## 5. 版本条

- 横向显示本会话所有版本，按生成顺序。每个版本是 80×80 的缩略图，下方标签"2D v2"、"3D v1"。一次出多张的结果是一个**组**，缩略图四宫格，标签 `2D v1 · 4 张`；点组可展开改选。
- 箭头表示来源：转 3D、截图、换贴图分别用不同图标的连接。来源未知时用虚线，标"来源未知"。
- 分支（从同一个旧版本生出两个以上新版本）：同一来源的多个结果竖向堆叠，共享来源连线；超过 3 个折叠为 +N。当前对象所在分支高亮，其他分支变淡。**原型必须展示一个有分支的会话。**
- 生成中的版本显示进度环；失败的显示红色角标，点开有[重试]。
- 当前版本有高亮边框。点击任一版本：舞台切换到它，对话输入区的"当前对象"同步。
- 右端加"定位当前"。←/→ 切换相邻版本。
- 生成完成时，只有当前对象是该任务来源且未在使用画笔/蒙版时才自动切换；否则显示"vN 已完成 [查看]"的常驻小条。
- 右端按钮"全部产出"：把版本条展开成整屏网格，可按 2D/3D 筛选，可按来源或日期分组。Shift 多选后"下载所选"；候选组可一键下载全部候选。

## 6. 顶栏

- 左：Logo、会话名（点击改名）、`▾` 会话列表（搜索、新建、删除需确认）。每行有最新版本缩略图、版本数、最后活动时间。进入会话时恢复上次的当前对象。
- 右：
  - 批准模式：`手工 ▾` 下拉，不是点击切换。下拉里说明两种模式的区别：手工模式下文生 3D、图生 3D、换贴图需要你批准。切到自动需二次确认：之后的文生 3D、图生 3D、换贴图不再询问。
  - 本会话积分：`本会话 32 积分`（悬停看明细）。
  - 任务中心：图标 + 运行数 + 总进度环。打开为右侧抽屉，列出全部任务，可取消、重试、定位到版本。
  - 余额：显示最低供应商余额并带供应商名，如 `Meshy 26`；低于阈值变黄。
  - 头像菜单：我的资源、管理后台（管理员）、退出。

## 7. 视觉

- 主题：深色（美术工具惯例，突出作品颜色）。界面用中性深灰，不带色相（#216）。
- 强调色是暖金（primary `oklch(0.827 0.141 92)`），用于主按钮、当前选中、进度和重点描边。
- 发送按钮是唯一的紫色例外（`--send` `oklch(0.518 0.229 280)`），不跟随主色。
- 状态色：成功绿、警告琥珀、错误红，只出现在角标和状态文字。
- 字体：系统中文字体栈（PingFang SC / Microsoft YaHei），数字用等宽。
- 圆角：面板 8px，按钮 6px，缩略图 6px。
- 间距：4px 网格。
- 图标：lucide-react，线宽 1.5。
- 所有图标按钮都有文字提示和快捷键提示。
- 继续遵守现有设计规则测试（token、层级、圆角刻度）。

## 8. 对现有怪异点的处理

| 现有问题（清单编号） | 新设计 |
|---|---|
| 聊天里看 3D 不切换域（1、2） | 没有域切换。舞台跟随当前对象。 |
| Agent 浮层盖住画布、和 3D 面板重叠（46、47） | 对话是固定左栏；处理和格式在右侧检查器。 |
| 操作只在悬停时显示（39–42） | 消息操作、图层操作常显。 |
| 删除消息无确认（9） | 删除要确认。 |
| 原生 confirm、原生 select（11、33） | 全部用 UI 组件。 |
| 图标与含义不符（35） | "适应"用 Maximize 图标，"100%"用文字。 |
| 文字编辑框固定在左上（38） | 文字在节点位置原地编辑。 |
| 背景样式只存本地、画布双份存储（3、4） | 画布状态只以服务器为准，本地只做缓存。 |
| 文案错误（5、12、49） | 新 Schema 文案统一审校。 |
| Enter 与输入法冲突（13） | 输入法组合中不发送。 |
| 同意对话框无超时提示（17） | 批准卡片显示有效期或过期态（见第 3 节）。 |
| 补齐格式无确认（10） | 按钮直接写积分，自动批准，不再写"需批准"。 |
| 撤销栈无 UI（20） | 工具栏加撤销/重做。 |

## 9. 开发方式（原型确认后）

- 保留：数据层（API 客户端、SWR、zustand 的业务状态）、Konva 画布引擎、`model-viewer`（过渡；线框、面数、通道视图需要换成 three.js 查看器，作为独立工作包）、Schema 文案机制、UI 组件库。
- 重写：工作台外壳（page、顶栏）、对话栏（由 agent-dialog 拆分）、舞台与舞台头、检查器、版本条、任务中心抽屉。
- 删除：顶栏域标签、Agent 浮层和移动端分支、历史对话框（由版本条和"全部产出"替代）。
- 新增 Schema 文案键 `ui.studio.*`；旧键在确认无引用后删除。
- 分步提交，每步都过 7 项门禁，测试同步更新。
- 需后端的功能列在第 10 节。开发前先确认；不确认的功能，界面上标"待接入"。另有一项小改动：服务端多存一个"当前版本"，用于第二天回来时恢复舞台。

## 10. 待后端支持

下面这些功能，后端现在做不到，或还没做完。界面可以先画，但不能画成已经能用。

- **真正的局部贴图修改（F5）。** 现在的换贴图是整套贴图重生，不能只改胸口一块。要改局部，需要贴图编辑接口。现在没有，界面不画。
- **持久的待批准步骤（F6）。** 另一项任务正在做。待批准步骤是批准卡片上还没点的付费步骤。要点：它不随本轮对话结束而消失；默认 24 小时内有效；过期后卡片显示"已过期 / 重新发起"；刷新页面后，待批准步骤还在列表里。
- **完整三视图（F7）。** 另一项任务正在做。要点：三个槽位（正、侧、背）；后两张自动接着生成，或由用户点"继续生成"；三张齐后记为一个组版本；图生 3D 只用正面那一张。
- **分享（F21）。** 不在计划内。界面不画分享按钮。
- **3D 查看器的线框和贴图通道（F22）。** 这是前端新能力，不是后端问题。要新做一个基于 three.js 的查看器，才能在浏览器里读模型文件，显示线框和面数，切换底色、法线、粗糙度通道。拿不到的数据显示"—"。

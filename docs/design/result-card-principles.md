## 一、三个问题的事实

### 0. 这两张图都来自同一个 Tripo 任务

- Tripo 文生 3D 会交回两张图，Schema 都标成 `thumbnail`（缩略图）角色（`internal/catalog/default_catalog.json` 约 12987–13006 行）：
  - `rendered_image`：Tripo 对**建好的模型**渲染的一张图。就是**左图**。
  - `generated_image`：Tripo **建模前自己先画的 2D 图**。就是**右图**。
- 3D 工具把 `thumbnail` 角色的图都放进消息图片（`internal/chat/generationtool/result.go:13`）。前端把消息图片一律画成“候选”，所以出现“2 张候选”。
- 服务端给第 1 张记成模型附件 `@model1`，第 2 张记成图片附件 `@img1`（`internal/chat/service_attachments.go:257`）。所以右图有 `@img1`，左图没有标签。
- **两张都不是用户意义上的“2D 候选”**。一张是模型的预览，一张是上游的中间图。

### 1. 为什么右边能“已选用”，左边不行

- 右图有图片附件 `@img1`。选用后服务端记下它，并找回句柄 `@img1`，前端认出来，按钮变“已选用”。
- 左图：
  1. 前端找附件只认图片类（`src/lib/chat/pick.ts:10`），左图的附件是模型类，找不到。
  2. 退回用“这条消息第一个任务的 ID”（`src/lib/chat/browser-client.ts:335–352`）。这里正好就是 Tripo 任务，所以服务端**接受了**这次选用。
  3. 服务端回传时找不到这张图的图片句柄（左图只有模型句柄，`internal/chat/attachments.go:181`），回传的选用没有句柄。
  4. 前端丢掉没有句柄的选用（`src/lib/chat/attachments.ts:67`），以为“什么都没选”，不报错。
- 结果：**服务端其实已经把左图（模型的渲染图）记成了本会话的当前对象**，界面却显示两张都没选。之后 Agent 说的“这张”指的是它。这是一个真实的缺陷，不只是体验问题。

### 2. 生成的是 3D，为什么进了 2D 画布

上面那张卡是**图片结果卡**（`ImageResultCard`）。它把每张图都当成 `kind: 'image'`。
舞台按类型分：图片走 2D 画布，模型才走 3D 查看器（`src/components/studio/stage.tsx:76`）。

能把你带进 2D 画布的入口：

| 入口 | 走的路径 | 结果 |
|---|---|---|
| 左图“选用” | 服务端接受后自动 `openOnStage(左图, kind=image)`（`result-card.tsx:166`） | 模型的渲染图以 2D 图片身份进画布（**错**，最可能是你遇到的） |
| 右图“选用” | 同上 | Tripo 中间图进画布 |
| 上卡“在舞台打开” | 作用于高亮的那张（先看你点过的，再看已选用的，都没有就是第一张，`result-card.tsx:58`） | 同上，以图片身份进画布 |
| 下卡“截图到 2D” | 先在舞台打开模型，再截一张图放进 2D | 故意去 2D（符合设计） |

同一个问题还带出一个错按钮：上卡的“转 3D”会把**模型的渲染图**再转一次 3D。

### 3. 怎样在卡里直接展示 3D

- **已有查看器可复用**：`src/components/viewer/model-viewer-3d.tsx`（基于 Google model-viewer）。舞台（`stage-3d.tsx:63`）、任务详情（`result-detail.tsx:138`）和比较视图（`compare-view.tsx:80`）都在用它。
- 现在的 3D 卡（`ModelResultCard`）只有文字和按钮，没有图，也没有查看器。
- 限制：浏览器对同时打开的 3D 画面数量有上限（具体数字随浏览器不同）。长对话里每张卡都实时转动，会丢画面、变卡。
- 推荐做法：用 `rendered_image` 做封面，加“3D”角标。点角标才在卡内加载可拖动旋转的查看器。同一时间只有一张卡在转，转别的卡时前一张退回封面。

## 二、设计原则草案

标记：**[推荐]** 是我的建议，可以直接定。**[待定]** 需要你拍板，后面附了我的倾向。

**P1 结果是什么，卡就是什么。** [推荐]
一个任务出一张卡。2D 任务出图片卡，3D 任务出 3D 卡。
模型的渲染图是 3D 卡的封面，不进 2D 候选，不带“选用”“转 3D”。

**P1b 上游的中间图放哪。** [待定]
Tripo 建模前画的 2D 图（右图）是真实的图，但不是你要的结果。
我倾向：**不放卡上**，放进任务详情和下载包。需要用时从任务详情拖出来。

**P2 “候选”只指同一次出的多张 2D 图。** [推荐]
“选用”的含义只有一个：定为本会话的当前对象，下一步默认从它继续。改选随时可以。

**P3 3D 要不要“选用”。** [待定]
我倾向**不要**。3D 一次只有一个模型；产品文档已写“3D 模型在舞台上即成为当前选中对象”。在舞台打开就够了。

**P4 每种动作只有一个入口。** [推荐]
现在同一张图有三个入口都打开任务详情：点图、右上角放大图标、“任务详情”按钮（`result-card.tsx:129,144,187`）。
“选用”还顺带做了“在舞台打开”。要去掉重复。

**P5 点卡里的图做什么。** [待定]
我倾向：**点图 = 在舞台打开**，2D 卡和 3D 卡一样。然后删掉“在舞台打开”按钮和放大图标。
任务详情保留一个小“ⓘ”入口。放大、比较已经在舞台上有。
注意：`docs/product.md` 第 99 行写“对话里点图片打开大图”，源码现在是打开任务详情，两者已经不一致。定了以后一起改。

**P6 按钮跟着对象类型给，不出现跨类型的按钮。** [推荐]

| 卡 | 点图 | 角标 / 每张下 | 卡底按钮 |
|---|---|---|---|
| 2D 图片卡 | 在舞台打开 | 每张下“选用” | 转 3D、下载、ⓘ |
| 3D 卡 | 在舞台打开（3D 查看器） | 封面“3D”角标：卡内转动预览 | 截图到 2D、下载全部（ZIP）、ⓘ |

**P7 结果卡、舞台、任务详情、画布各管一件事。** [推荐]
- 结果卡：看一眼，做最常用的下一步。不编辑。
- 舞台：看和操作当前对象。2D 走画布，3D 走查看器。放大、比较、截图都在这里。
- 任务详情：只放事实（参数、积分、来源、格式、失败原因）。
- 画布：只放 2D。3D 进画布只有“截图到 2D”这一条路。

**P8 任务详情里的动作按钮怎么办。** [待定]
任务详情现在也有“发到 3D / 发送到 2D / 在画布中打开”（`docs/product.md` 第 101 行），和卡上的按钮重复。
我倾向：任务详情**只留“下载”**，其他动作只在卡和舞台上。定了要改产品文档。

**P9 最高质量不给选择，内部名不上屏。** [推荐]
3D 卡上“可用格式：converted.gltf”显示的是 Schema 里的格式变体名，用户看不懂，也不用选。删掉这一行；格式只在下载包和检查器里。

**P10 点了就有反馈。** [推荐]
- 对这类对象没有意义的按钮直接不显示（比如 3D 卡不出“转 3D”）。
- 暂时不能用的按钮（比如属于别的会话）置灰，并在悬停时说原因。这一条和 `docs/product.md` 第 101 行一致。
- 点了失败要说原因。**点了成功却没变化**（今天的左图选用）是最坏的情况，必须消灭。

**P11 积分只说一次。** [待定]
现在一张截图里出现三次：卡头“约 50 积分”、卡下“本步消耗 50 积分”、“重新生成（约 50 积分）”。
我倾向：留“本步消耗”和重新生成按钮上的价格，删卡头那一处。

1. 3D 任务的 `thumbnail` 图不再进消息的 2D 候选：渲染图做 3D 卡封面，中间图按 P1b 的决定处理。

## 五、延伸：舞台能不能同时放 2D 和 3D

### 现在的做法（源码事实）

- 舞台一次只放一个对象，按类型二选一：图片走 2D 画布，模型走 3D 查看器（`src/components/studio/stage.tsx:76`）。
- 2D 画布里没有 3D 图层。画布的“虚线框”栅格化成一张图，交给 2D 上游。
- 3D 查看器选中模型后，右侧检查器给 3D 动作：模型加工、格式、详情（`src/components/studio/inspector.tsx:34`）。
- 跨类型已有三座“桥”：截图到 2D（3D→2D）、转 3D（2D→3D）、用这张图换贴图（2D 图 + 3D 模型 → 新 3D 模型）。
- 比较视图在源码里已经能把图片和模型并排放（`src/lib/workspace/compare.ts:13`，`compare-view.tsx:309`），只能看，不能改。
  注意：`docs/product.md` 第 99 行还写着“3D 模型不能放进比较”，和源码不一致，需要核对。

### 核心问题

数据交给 2D 上游还是 3D 上游，不应该由“舞台上显示了什么”决定，而应该由“你选中了什么、点了哪个动作”决定。
如果 3D 模型能当图层放进 2D 画布，用户在框里局部重绘，系统只能悄悄按当前视角把模型截成图，再交给 2D 上游。
用户以为在改模型，拿回来的却是一张图。这正是“给用户错误理解”。

### 原则草案（续）

**P12 动作决定输出类型，不是舞台决定。** [推荐]
每个动作写明“吃什么、吐什么”，按钮文字说清结果是图还是模型。

| 动作 | 输入 | 输出 | 上游 |
|---|---|---|---|
| 重绘 / 局部重绘 | 2D 图（虚线框） | 新 2D 图 | 2D |
| 截图到 2D | 3D 模型（当前视角） | 2D 图 | 不调上游 |
| 转 3D | 2D 图 | 3D 模型 | 3D |
| 用这张图换贴图 | 2D 图 + 3D 模型 | 新 3D 模型 | 3D |
| 模型加工（减面、绑骨等） | 3D 模型 | 新 3D 模型 | 3D |

**P13 选中什么，就作用于什么。** [推荐]
2D 画布里选区域或图层，给 2D 动作。3D 查看器里选模型，右侧给 3D 动作。不出现“选的是模型、做的是 2D”的情况。

**P14 看可以混放，改只对一种类型。** [推荐]
比较视图、版本条可以把 2D 和 3D 放在一起看。编辑区一次只有一种类型。

**P15 跨类型只走写明的桥。** [推荐]
只有“截图到 2D”“转 3D”“用这张图换贴图”这三座桥能跨类型。每座桥的按钮说清会变成什么，比如“截图到 2D（生成一张图）”。没有隐式截图。

**P16 3D 不进 2D 画布当图层。** [待定]
我倾向**不进**。要在画布里用模型的样子，先“截图到 2D”；截图会记住来源模型，版本条能连回去。

**P17 要不要“并排舞台”（左 3D、右 2D）。** [待定]
适用场景：你说的“模型和贴图放在一个区域”，比如边看模型边改贴图。
如果做：两格各有自己的工具和动作，谁有焦点就作用于谁，框线高亮当前格。动作仍按 P12 的表决定上游。
我倾向**先不做**。现有“用这张图换贴图”已经能把 2D 贴图交给 3D 上游；等真有“边改贴图边看效果”的需求再做。

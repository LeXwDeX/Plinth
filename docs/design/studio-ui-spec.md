### 独立模型来源交互

右侧“功能”中的模型来源与舞台对象、输入区生成模型各自独立。入口是否出现、文件限制和附加要求来自所选服务的公开 Schema；支持的服务允许选择本人本会话已完成模型，或上传/选择本人原生模型文件。文件名和大小以服务端返回为准，刷新后恢复已保存来源；仅上传和换选不保存、不执行，用户明确保存后用于下一轮。上传或保存失败保留原草稿及原已存选择，冲突读取服务器版本并提示重新确认，不自动覆盖。

切会话、用户、服务或来源模式时，迟到响应不能污染当前面板；同会话离开后返回也适用。版本链里的模型上传节点只说明来源事实，没有生成任务，不提供虚构任务详情，也不通过假 Task ID 切换舞台。源码契约与验收边界见 `docs/architecture.md` 和原生 Issue #182。

### 失败任务的本地产物恢复

只有服务端在失败任务详情中确认的本地恢复资格，才在共享结果详情显示入口；UI 不根据文件 URL、任务错误文本或客户端上传状态推断资格。恢复只使用服务端返回的收据摘要，并通过普通公开 Task 的授权、批准和提交流程创建独立任务。自动批准按 Grant 的 `status` 处理；待批准时明确显示批准和拒绝操作，并在刷新后恢复待处理决定。拒绝不会提交任务。关闭详情、切换会话或来源会使当前面板的异步操作失效：旧响应不打开任务、不显示提示、不更新面板或待批准存储；重入同一来源也不会恢复旧请求的 UI 权限。每次后续 Grant、决定或 Task 写请求前重新检查该次挂载身份；已经发出的已授权 Task 请求仍可在后台完成，再次进入通过公开资格查询找回既有 Task。

恢复结果保留来源任务链接；来源任务也可打开已有恢复任务。重新进入、重复点击或并发准备应重新使用服务端给出的既有 Task，不覆盖原失败记录、历史费用或当前画布/Scene。新恢复 Task 加入任务列表和结果详情，但不自动成为舞台对象。按钮文案和路由均来自可选的 `task_history.asset_recovery` Schema 块；旧 Schema 没有该块时不显示恢复控件。

## 第一部分：UI 规范

### 1. 颜色

底色、面板、文字与交互态取中性深灰阶，强调色取暖金（#216）；类型与品牌标记在 `src/app/globals.css` 统一声明：

| 名称 | 值（当前源码） | 用在哪 |
|---|---|---|
| `--kind-2d` | `oklch(0.79 0.115 195)`（青） | 2D 标记的图标和文字 |
| `--kind-2d-soft` | 同上，16% 透明度 | 2D 标记的底色 |
| `--kind-3d` | `oklch(0.80 0.14 65)`（橙） | 3D 标记的图标和文字 |
| `--kind-3d-soft` | 同上，16% 透明度 | 3D 标记的底色 |
| `--ai-mark` | `#f3c947`（暖金） | ✦ 标记、说明里的积分行 |

规则：
- 青和橙只用来表示 2D / 3D，不拿来做别的强调。
- 主色 `--primary`（暖金 `oklch(0.827 0.141 92)`）表示“当前选中”“主要按钮”和重点描边。
- 发送按钮保留独立紫色 `--send`（`oklch(0.518 0.229 280)`），不跟随主色；其余主操作以暖金为准。
- 成功、警告、错误照旧用现有的绿、黄、红。
- 页面、面板、卡片、输入底与边框只从既有 token 取值，不在页面里散落色值副本。
- 画布上的画板虚线框与蒙版取样色由 Product Schema `application.canvas.frontend.export.frame.stroke_color` 与 `application.canvas.frontend.selection.tint_color` 声明，取主色暖金 `#e7c34b`；两者需与 `--primary` 的实际渲染值保持同步（#216）。

### 2. 类型标记（KindBadge）

- 样子：图标 + 文字，`[图片图标] 2D` 或 `[立方体图标] 3D`，11px 字，圆角 5px，底色用 soft 色。
- 只有这一种写法。不再单独用不带颜色的图标表示类型。
- 出现位置：舞台工具条左端、版本条每个方块、对话结果卡标题、输入框里的引用芯片、右侧栏“详情”的“类型”行。

### 3. ✦ 标记（会调用模型）

- 带文字的按钮：✦ 跟在文字后面，10px，`--ai-mark` 色。
- 只有图标的按钮：✦ 缩成图标右上角的一个小点，颜色相同。
- 局部重绘、去背景、转 3D、用这张图换贴图、补齐格式沿用各自的模型调用、可能费用标记。3D 加工入口按公开 `canvas.frontend.processing_action.calls_model` 显示标记，默认 `false`：没有 ✦、图标圆点或费用强调色。点击只打开加工设置，是否调用模型及所需积分以所选方案为准。
- 不给：截图到 2D、合并为新版本、导出画板、发送到对话、比较、大图。

### 4. 舞台上方工具条

高 44px。从左到右分四组，组间用竖线隔开：

| 组 | 2D | 3D |
|---|---|---|
| 身份 | 类型标记、版本号、句柄、来源 | 同左 |
| 产出（✦ 为主） | 局部重绘 ✦、去背景 ✦、转 3D ✦、用这张图换贴图 ✦；画板有改动时最前面多一个“合并为新版本” | 截图到 2D；每个可用加工步骤一个入口按钮，默认无 ✦（分组由 `processing_action.group` 声明，默认 `produce`） |
| 输出 | 发送到对话、导出画板（只用图标） | 无 |
| 查看 | 比较、大图（只用图标） | 比较（只用图标） |

- 现在舞台宽于 64rem（1024px）才显示文字（`stage-header.tsx:43`）。1440 宽的屏幕上舞台约 780px，所以**平常其实只显示图标**。这让悬停说明（R16）和图标一一对应（R14）更重要。
- 空间不够时，按“查看 → 输出 → 产出”的顺序先收文字；身份组不收。
- 旧版本时，身份组多一个“旧版本”标签，产出组最前面多一个“从这里继续”按钮（现状如此，`stage-header.tsx:159–174`）。
- 画板有内容、但还没有版本时：身份组写“画板”（2D 标记），产出组只有“合并为新版本”，输出组有“发送到对话”“导出画板”。现在这种状态的工具条只有“导出画板”（`stage-header.tsx:89–96`），要补上。
- “去背景”的对象：画布里选中了图层，就去选中图层的背景；没选，就去当前版本这张图的背景。现在工具条上的去背景总是作用于当前版本这张图（`workspace-canvas-board.tsx:764–765`），要改。改好以前，不能删浮条上的去背景，否则选中上传图层去背景的路就断了。

### 5. 左侧工具栏（2D）和视图条（3D）

同一个组件，放在舞台左上角，浮在画布上。

| 状态 | 宽度 | 按钮 |
|---|---|---|
| 收起（默认） | 约 38px | 只有图标，30×28px |
| 展开 | 按最长名字，至少 96px | 图标 + 名字 |

- 底部最后一个按钮是开关：收起时是“»”，展开时是“« 收起”。
- 展开或收起由这个浏览器记住；2D 和 3D 共用一个记忆。
- 2D 分组（组间横线）：
  1. 选择类：选择、抓手、矩形选框、套索选区、蒙版、吸管、缩放工具；
  2. 绘制类：上传图片、形状、文字、铅笔、画笔、橡皮、裁剪；
  3. 吸附；
  4. 撤销、重做；
  5. 展开开关。
- 3D 分组：贴图、白模、线框；展开开关。图标见 §9，不再借用 2D / 3D 标记的图标。
- 当前工具：主色淡底 + 主色图标。

### 6. 右侧栏

- 宽 300px，常驻，不能收起（R4）。只有一层（R4b）。
- 顶部 44px 是标签条：图标 + 文字，当前标签下面一条 2px 白线。
- 内容区内边距 12px，内容全部平铺，长了就滚动。
- 需要确认的按钮（开始加工、补齐格式）固定在底部，宽度占满。
- 空状态：一句话，13px，次要文字色。

| 类型 | 标签（默认在前） |
|---|---|
| 2D 图片 | **图层**、历史、详情、功能 |
| 画板有内容但没有版本 | **图层**、历史、功能（没有对象，所以没有“详情”） |
| 3D 模型 | **功能**、加工、格式、部件、详情 |
| 什么都没有 | 不显示标签，直接显示功能选择；未选会话时提示先选会话 |

- 每种类型记住上次停在哪个标签（2D 一份、3D 一份，只在这次打开页面期间记），标签顺序和默认值读取 Schema。
- 功能页保存会话选择，原加工页管理人工计划。功能页明确保存不会执行；输入框上方显示本轮与下一轮选择的差别，并随轮次边界刷新。已保存功能时发送按钮不显示生成模型的费用；回到自由模式且当前会话选择已确认后恢复生成估算。此入口契约随 #181 更新，不更改四个生成模型/Skill/范围/参数选择器的含义。
- “格式”标签里的“补齐格式”：确认、进度、暂停后继续都在这一页完成（R8）。现在继续只能在加工页做（`model-processing-panel.tsx:301–307`），格式页只显示“已暂停”（`model-formats.tsx:160`）。

### 7. 画布浮条

- 选中图层时出现在画布右上角，只用图标。
- 左边先写选中图层的名字，后面是：复制一份、下载这一层、删除这一层。
- 不放任何会调用模型的动作，也不放“发送到对话”“转 3D”。

### 7.1 画布像素尺寸（#246 阶段 1）

- 虚线框就是画布：世界坐标 1 单位 = 1 像素，画布以 Schema 锚点为中心。虚线框内左上角的小字写“工作区：宽×高，比例”（#282，`ui.canvas.size.label`），衬一块半透明底板（Schema `artboard.label` 的 `padding_pixels`、`background_token`、`background_opacity`），离框 `offset_pixels`，随缩放保持屏幕字号，超出框的部分裁掉，不接收指针。
- 虚线框保持居中（#282）：框中心在可视区中心（1 像素容差）时，滚轮、捏合、缩放工具绕可视区中心缩放，绘图区尺寸变化时平移量补偿一半的尺寸差；框被用户平移开后，这些缩放回到以指针为中心，尺寸变化不再补偿。
- 适应屏幕不被浮动控件遮挡（#246）：适应屏幕、Ctrl+0、进入舞台、回到画布和缩放到选区都按 `stageFitInsets(railExpanded)`（左侧工具栏收起 64、展开 138，上 56，右 16，下 64）留白；为了保持 #282 的居中，左右各取两侧较宽的一条，上下同理，框中心仍在绘图区正中。
- 虚线框的线宽和虚线段是屏幕像素（Schema `artboard.frame_stroke_width`、`frame_line_dash`，关闭描边缩放后由 Konva 按屏幕像素绘制），任何画布尺寸和缩放下看起来一样。
- 2D 模型的输出尺寸和画布尺寸不一致时，画布顶部居中（工具选项栏下方）出现一条提醒（`canvas-size-notice`，提醒色底），同样的提醒也在参数弹层 2D 区的尺寸下方：能对齐时给“按画布尺寸输出”，不能时写明模型将输出的尺寸并给“画布改为 W×H”。一致时不显示任何东西。
- 参数弹层 2D 区尺寸下方常驻一行说明（`ui.canvas.size.resize_hint`），下面是改尺寸锚点：“改尺寸锚点”小字加 3×3 方格单选（`canvas-resize-anchor`，每格悬停说明为 `ui.canvas.size.anchor.*`，选中格为主色），Schema 未提供的锚点置灰。缩小截到图层时弹出一次提示（`ui.canvas.size.clipped`）。
- 新画布的“画布图层”（`ui.canvas.layers.initial_name`）出现在图层面板第一行，与其他图层同样有显示、锁定、删除按钮；未画过时在画布上不响应点击。画笔点到画框内没有图片的地方时，自动在最底层新建一个画布图层接住笔画（悬停时画笔预览显示为可画）。
- 画框内、所有图层之下是透明棋盘格（Schema `artboard.transparency`：格子 8 屏幕像素，白/黑交替，透明度 0.08，深浅主题下都很淡），表示导出时透明的区域；导出背景为颜色时改为该颜色填充。
- 尚未实现：整体缩放内容、破坏性裁切。

### 8. 悬停说明（Tooltip）

| 项 | 规定 |
|---|---|
| 出现 | 鼠标停 350ms；键盘移到按钮上立刻出现；移开、点击、Esc 消失 |
| 位置 | 按钮下方 8px，放不下就放上方；不超出窗口 |
| 大小 | 最宽 260px，12px 字 |
| 内容 | ① 名字 + 快捷键；② 做什么；③ 作用于谁；④ 积分行（✦ 会调用模型……／免费，不调用模型） |
| 置灰按钮 | 也要能显示说明，第一句写为什么不能用 |

结果详情弹窗打开时，初始焦点放在带有结果名称的标题上（`tabIndex=-1`，只作程序化焦点，不加入 Tab 顺序），避免自动聚焦预览动作后弹出提示。Tab 仍按页面顺序进入操作与下载格式，关闭后恢复打开前的焦点；焦点位于提示触发项时，Esc 关闭提示并保留详情弹窗。鼠标悬停提示期间的 Esc 沿当前焦点所属的弹层处理，可能同时关闭详情弹窗。

结果详情弹窗的尺寸固定（`min(92dvh, 44rem)`），同组翻页行与固定预览框（`min(42dvh, 24rem)`，无预览的文件为 6rem）在滚动区之外，只有字段、动作与下载区在剩余空间内滚动；翻页键位取 Schema 的 `chat.frontend.lightbox_previous_key` / `lightbox_next_key`，输入控件获得焦点时不触发。

## 第二部分：代码框架

目标：上面这些规则只在一个地方声明，工具条、工具栏、浮条、右侧栏、说明气泡和快捷键面板都从这里读。符合项目约定“可变产品配置由 Product Schema 声明”。

### 1. Schema 里新增三张表

现在的 `ui.studio.*` 只是 `application.content.messages` 里的扁平文案键，Go 不校验它们的结构（`schemaText`，`product-schema.ts:1641`）。三张表要做成有类型的块，放在 `canvas.frontend` 旁边（`schema_types.go:1317` 附近），并且同一次改动里补齐：
- Go 类型和校验（`canvas_validation.go` / 应用级校验）：id 唯一、文案键存在、图标名非空、快捷键不和 `reserved_shortcuts` 冲突；
- TypeScript 类型（`product-schema.ts`）；
- 公开投影和 fixture（`catalog_test.go:884–888`、`canvas_audit_schema_test.go:197`、`browser-client.test.ts:182–198`）。

**动作表 `actions`**：每个工具条按钮一条。

| 字段 | 例子 | 说明 |
|---|---|---|
| `id` | `inpaint` | 前端按 id 接上处理函数 |
| `kinds` | `["image"]` | 在哪种对象上出现：`image` / `model` / `board` |
| `group` | `produce` | 身份以外的三组：`produce` / `output` / `view` |
| `calls_model` | `true` | 决定 ✦ 和说明里的积分行 |
| `cost_hint` | `approval_card` / `process_panel` / `free` | 积分行写哪句 |
| `icon` | `wand-sparkles` | 图标表里的名字 |
| `label_key` / `hint_key` / `target_key` | 文案键 | 名字、做什么、作用于谁 |
| `shortcut` | 可选 | 引用现有 `keyboard` 设置 |

3D 加工入口按“当前可用的加工能力”生成，名称、图标来自能力声明；通用展示读取公开 `canvas.frontend.processing_action` 的 `calls_model`、`cost_hint`、`group`，默认分别为 `false`、`process_panel`、`produce`。`cost_hint` 选择 Schema 提示文案，`calls_model` 只控制标记及费用强调色，`group` 控制真实分组并沿用该组的仅图标规则；`approval_card` 必须有标记，`free` 不允许标记，`process_panel` 允许无标记的中性导航。入口不选择 Offering、不执行任务，也不按 Provider、能力 ID 或积分推断执行方式；实际方案的调用与积分在加工设置中核实。图标使用能力的 `icon` 字段，不另建前端图标表。

前端保留一张“图标名 → lucide 组件”的对照表。它只负责把名字变成图标，不带任何产品含义；哪个按钮用哪个图标只在 Schema 里写。

**工具表 `tools`**：左侧工具栏和 3D 视图条每个按钮一条，字段同上，多一个 `rail`（`canvas` / `viewer`）和 `section`（分组）。

**右侧栏表 `panel_tabs`**：每种对象一组标签。

```
image: [layers, history, details]   默认 layers
board: [layers, history]            默认 layers（还不是版本，没有详情）
model: [process, formats, details]  默认 process；无可用步骤时 details
```

### 生成参数的数量与禁用状态

生成数量及输入区完整参数摘要显示当前 Offering 的有效参数值，不取报价乘数。步进器具有可辨认边框、hover 和键盘焦点；达到 Schema 最小或最大值时，仅对应方向的按钮禁用，悬停与辅助说明给出边界原因。缺少会话、参数未就绪、Offering 不可用及 Schema 条件禁用时，控件整体显示为不可编辑并说明原因；条件禁用不篡改已保存值。比例、依赖项和“更多参数”同样解释条件禁用。建议只读项保留“不建议更改”及 Schema 理由，不渲染可交互控件。所有文案取 Product Schema `ui.studio.params.*`。

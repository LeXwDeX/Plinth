# Plinth 新工作台原型：美术视角的 UX 验证

- 日期：2026-10-08
- 对象：`docs/design/redesign-spec.md`（方案）与原型 `design-canvas/project/`（原型未入库）（Main 交互流程步骤 0–6；Stage2D、Stage3D、Tasks、AllOutputs 四张静态细节图）
- 依据：`docs/product.md`（后端真实能力）、`docs/design/frontend-inventory.md`（现有界面与 50 条怪异点）
- 方法：不渲染原型，逐行读标记和 `renderVals()` 状态机，按四个美术角色的日常任务一步步走。
- 本文只写发现和改法。不改原型，不改方案。

名词先说清，后面不再解释：

- **舞台**：中间的大区域，显示当前这一张图或这一个模型。
- **检查器**：右侧 300px 面板。显示提示词、图层、3D 处理和格式。
- **版本条**：底部 112px 的横条。每次生成算一个版本，按顺序排。
- **版本链**：版本之间“谁来自谁”的关系。比如 3D v1 来自 2D v1。
- **分支**：从同一个旧版本生出两个以上的新版本。
- **句柄**：对象的短名字，如 `@img5`、`@model1`。在对话里用它指图或模型。
- **候选**：一次出图得到的多张图，用户从中选一张“选用”。
- **蒙版**：在图上涂出一块区域。**局部重绘**：只让模型重画蒙版里的区域。
- **三视图**：同一角色的正面、侧面、背面三张图，给建模用。
- **换贴图**：3D 模型形状不变，重新生成一套表面贴图。
- **重拓扑**：重新生成模型的面，通常是减面、变整齐。**绑骨**：给模型装骨架。**动画**：用骨架做动作。
- **面数**：模型由多少个三角面组成。**线框**：只看面的边线。**白模**：不显示贴图，只看形状。**UV**：贴图在模型表面的展开方式。
- **供应商**：Meshy、Tripo、OpenAI 等提供模型的公司。**余额**：公司账户里剩的点数，不是个人积分。
- **批准模式**：手工模式下，文生 3D、图生 3D、换贴图三种付费动作要人点“批准”；自动模式全部自动。
- **设定摘要**：对话栏顶部的一段文字，记录已敲定的设定。Agent 每轮都会看。
- **灯箱**：点一张图，整屏放大看。
- **聚焦模式**：一键隐藏对话栏和检查器，只留舞台。

---

## 1. 结论（5 行）

1. “对话 + 舞台 + 检查器 + 版本条”的骨架对这四类美术是对的。一个当前对象、动作就近、版本常驻，这三条都解决了现有界面最大的痛点（域切换、浮层遮挡、历史藏在弹窗里）。
2. 但原型只走通了一条“角色往返”主线。美术每天最常做的事——定尺寸、出一批、放大看、并排比、改选、分支——原型里要么没有，要么被挡住。这些是 P0。
3. 有四处原型承诺了后端做不到的事：批准卡片“一直等”（后端 120 秒超时）、换贴图“其余保持不变”（后端只能整套重生）、三视图自动出三张（后端只自动跑第一张）、多视图转 3D（后端不支持）。必须按真实能力重写文案和流程，否则上线即失信。
4. 文案和规则有六处与 `product.md` 冲突：切换模式会补批准、重拓扑/绑骨/动画被写成要批准、补齐格式被写成要批准、余额不足还给“重试”、换贴图提示词和风格图没有二选一、Meshy 来源显示可转 glTF。都是 P1，但改起来便宜。
5. 建议顺序：先补“参数行 + 灯箱 + 比较视图 + 候选组可改选 + 分支显示”，再按后端真实能力改批准和换贴图，再补三视图流程。布局本身不用推翻。

## 2. 逐场景走查

严重度：**P0** 做不成任务；**P1** 每天都难受；**P2** 打磨。
“原型是否覆盖”：**是**＝原型里能点出来；**部分**＝有界面但点不通或只到一半；**否**＝没有。

### 2.1 场景一：2D 角色美术

### 2.3 场景三：3D 角色美术

| 步骤 | 操作路径 | 原型是否覆盖 | 问题 | 严重度 |
|---|---|---|---|---|

| 5. 重拓扑、绑骨、动画 | 舞台头“处理” → 检查器“处理”页 → 分段按钮选一项 → 开始 | 部分（`procStart` 只在步骤 6 的换贴图上有反应） | 三个问题：① 说明文字写“手工模式：点击开始后，对话里会出现批准卡片”，但 `product.md` 说重拓扑、绑骨、动画自动批准，只有换贴图要批准。② 绑骨页写“当前模型是 A 字站姿，可以直接绑骨”，后端没有站姿检测，这是编的。骨架“四足 / 自定义”是否可选待核对接口。③ 三步是链式的（动画要先绑骨），处理页没有显示“哪一步已做、下一步可做什么”，也没显示每一步会生成一个新 3D 版本。 | P1 |

|---|---|---|---|---|
| 1. 3D v1 胸口贴图有问题 | 版本条点 3D v1 → 转到看胸口 | 是 | 看不出贴图问题在哪一张贴图上（没有贴图通道视图）。 | P2 |
| 2. 截图到 2D，画修改，发回换贴图 | 舞台头“截图到 2D”（0 积分）→ 2D v2 → 蒙版 + 对话“改成金色花纹”→ 2D v3 → 卡片“发回 3D 换贴图”→ 批准卡片（@model1 + @img6，约 10 积分）→ 3D v2 | 是（步骤 4→5→6） | 这是原型最完整的一段，流程顺。但承诺错了：换贴图提示词写“其余贴图保持不变”，Meshy 换贴图是以风格图为参考**整套重生**，不能只改胸口。美术会以为是“把我画的贴上去”。另：`product.md` 说换贴图“提示词与风格图二选一”，原型两者同时填。截图是“当前视角”，美术通常要正面正交视图，没有选项。用画笔直接在截图上画（不用蒙版）时，画好的笔画怎么变成一张可发送的图，原型没有路径。 | P0（期望与后端能力不符） |

| 4. 交给同事 | 无 | 否 | 产品没有分享。会话按人隔离，同事打不开。只能下载 PNG / ZIP 再传。版本链、提示词、设定摘要都带不走。 | P1（需要后端：共享链接或交接包） |
| 5. 第二天回来找 | 顶栏会话名 ▾ → 列表（名字 + “昨天”）→ 点进 → 版本条 / 全部产出 | 是 | 会话列表没有封面图，只有名字；名字如果没改就是“新会话”。进会话后舞台显示哪个版本没定义（原型按步骤算）。“全部产出”按生成顺序排，8 个以内还行，50 个以后要翻很久，没有按日期分组。 | P1 |

## 3. 汇总发现（按严重度，已去重）

每条写明区域和具体改法。标 **[需后端]** 的，后端现在做不到，不能画成能用的样子。标 **[需前端新能力]** 的，后端有数据或能力，但现有前端组件不支持。

### P0

**F1. 没有尺寸、比例、张数。**
区域：对话栏输入区。
改法：在 `2D ▾ 3D ▾ Skill ▾` 那一行左侧加一个“参数”按钮，点开是一个小面板：比例（1:1、2:3、3:2、16:9、9:16）、尺寸（随模型可选项）、张数（1–10，默认 4）。选定后以芯片形式显示在输入框上方，如 `16:9 · 4 张`。Skill 带推荐尺寸时自动填入并提示“来自 Skill”。费用随张数实时变（4 张 × 6 = 24 积分）显示在发送按钮旁。后端 `set_params` 已支持。

**F2. 候选和版本看不大、不能并排。**
区域：舞台。
改法：① 点任何一张候选或版本缩略图，按 Space 或双击进入灯箱：整屏、可 100%、←/→ 翻页、Esc 退出，灯箱里直接有“选用”。② 舞台头加“比较”动作：把舞台分成 2 格或 4 格，每格从版本条拖入或从下拉选一个版本；同步缩放平移；对 2D 另加滑杆对比。③ 加聚焦模式：Tab 键收起对话栏和检查器，再按恢复。前端即可，不需后端。

**F3. 候选组选用后不能改选，其余候选消失。**
区域：版本条、舞台。
改法：一次出图在版本条上就是一个“组”版本（如 `2D v1 · 4 张`），缩略图用四宫格。点组可以展开看全部候选并改选；改选不删旧结果，只改当前对象。组里任何一张被用来继续生成时，版本条从那一张分出分支。对话里“选用”按钮不要在后续步骤禁用。后端“选用”本来就允许改选。

**F4. 分支从没画过。**
区域：版本条、全部产出。
改法：版本条按方案说的“上下叠放”，但要真画出来：同一来源的多个结果竖向堆叠，共享一条来源线；超过 3 个折叠成“+N”。当前对象所在的分支高亮，其他分支变淡。全部产出的网格加“按来源分组”视图。这是方案 §5 已写但原型未证明的点，必须在下一版原型里出现。

**F5. 换贴图被当成局部修贴图。** [需后端才能真做局部]
区域：对话卡片、检查器处理页。
改法：文案改成实话。卡片按钮“发回 3D 换贴图”改为“用这张图换贴图”，卡片下写一行：“会按 @img6 的风格重新生成整套贴图，不能只改一块。”检查器处理页去掉“其余贴图保持不变”默认提示词；提示词和风格图做成二选一的分段切换，不能同时填。结果卡片写“3D v2 · 整套贴图重生”。真正的局部贴图修改需要 UV/贴图编辑接口，现在没有，不要画。

**F6. 批准卡片“一直等”与后端 120 秒超时矛盾。** [需后端]
区域：对话栏批准卡片、顶栏批准模式。
改法：两选一。(a) 后端把待批准步骤改成持久化，不随轮次结束而失效；界面才能写“一直等”。(b) 后端不改时，卡片 120 秒后进入“已过期”态，按钮变成“重新发起（会重新冻结输入）”，并在舞台气泡和版本条占位上同步显示“已过期”。无论哪种，切换批准模式**不得**回头批准挂着的卡片；原型 `toggleMode` 里那段 `approve()` 要删。

**F7. 三视图没有流程。** [后端只自动跑第一张]
区域：舞台头、对话卡片、版本条。
改法：2D 对象的舞台头加“三视图”动作（或 Skill 菜单里内置一项）。结果是一张“三视图卡片”：三个槽位（正 / 侧 / 背），第一张自动出，后两张各有“继续生成（约 6 积分）”和状态；全部完成后合成一个组版本 `2D v3 · 三视图`，缩略图三格。版本条用一个组表示。转 3D 时明确只用正面那一张，并在批准卡片的输入图上标“正面”。

## 5. 真实前端的验收场景

在做好的前端上按步骤跑。每步有通过条件。数字按 `product.md` 的积分和规则。

### 5.1 场景一：2D 角色美术

1. 新建会话。点起步卡“从文字出图”。**通过**：输入框被填好，积分不变，参数芯片显示 `1:1 · 4 张`。
2. 把参数改成 `2:3 · 6 张`。**通过**：芯片更新；发送按钮旁显示“36 积分”。
3. 输入“赛博朋克女刺客，全身立绘”，Enter。**通过**：对话出现 6 张候选组；版本条出现 `2D v1 · 6 张` 四宫格；本会话积分 +36。中文输入法选字时按 Enter 不发送。
4. 按 Space 打开灯箱，←/→ 翻 6 张，在第 3 张点“选用”。**通过**：舞台显示第 3 张；芯片“当前：@img3”带缩略图；检查器详情显示提示词和 `2:3`。
5. 回到候选组改选第 5 张。**通过**：允许改选；版本条组不变；芯片变 @img5。
6. 输入“换成红黑配色，出 3 张”。**通过**：Agent 回复第一行写“基于 @img5”；新组 `2D v2 · 3 张` 在版本条上作为 v1 的分支显示。
7. 舞台头点“三视图”。**通过**：三视图卡片出现；正面自动生成；侧、背各有“继续生成（约 6 积分）”；全部完成后版本条出现 `2D v3 · 三视图`。
8. 把 `2D ▾` 改成 Nano Banana Pro，舞台头点“局部重绘”。**通过**：参数条提示不支持蒙版并提供一键切换；切换后进入蒙版。
9. 涂胸甲，按 Enter。**通过**：输入框上方出现“蒙版 · @img5”芯片。
10. 输入“改成金色花纹”，发送。**通过**：新版本只改了蒙版区域；来源连线写“局部重绘”；积分 +6。
11. 切到别的版本再切回 @img5。**通过**：未发送的蒙版还在。
12. 全部产出里 Shift 多选 4 张，点“下载所选”。**通过**：得到 4 个 PNG，文件名含版本号。

### 5.2 场景二：2D 场景美术

1. 参数选 `16:9 · 4 张`，输入“黄昏雨后的废墟街角”。**通过**：4 张都是 16:9。
2. 在 1280×720 窗口按 Tab。**通过**：对话栏和检查器收起，舞台宽不少于 1100px；再按 Tab 恢复。
3. 选用一张，输入“同一构图，出 3 个天气：雪夜、正午、雾”。**通过**：3 个新版本作为分支堆叠显示。
4. 点回形针上传一张草图；在附件芯片选“参考构图”。**通过**：芯片带缩略图；版本条和全部产出里标“上传”，不出现“来源未知”。
5. 输入“按草图的构图重画”。**通过**：结果来源连线指向草图和当前图。
6. 舞台头点“比较”，拖入雪夜和正午两版。**通过**：两格同步缩放；滑杆对比可用；Esc 退出。
7. 蒙版修左下角一块，发送。**通过**：参数条不遮住图的上沿；只有该区域变化。
8. 下载当前版本。**通过**：PNG 尺寸与检查器显示一致。

### 5.3 场景三：3D 角色美术

1. 打开有三视图组的会话，版本条点 `2D v3 · 三视图`。**通过**：舞台显示三张；舞台头“转 3D”可点。
2. `3D ▾` 选 Meshy 7.1，点“转 3D”。手工模式。**通过**：批准卡片显示输入图标“正面”、约 35 积分、Meshy 当前余额；余额低于 35 时“批准”置灰。
3. 批准。**通过**：进度卡显示百分比和已用时间；版本条出现进度环占位；顶栏任务数 1；舞台可继续操作其他版本。
4. 生成期间在 2D v1 上开蒙版涂抹。任务完成。**通过**：舞台**不**自动切换；出现“3D v1 已完成 [查看]”小条。
5. 点“查看”。**通过**：舞台进入 3D；左侧贴图/白模/线框可切；右下显示面数和贴图尺寸，或“—”。
6. 批准卡片勾选“同时用 Tripo H3 再生成”。**通过**：两个 3D 版本作为 2D v1 的分支并列；比较视图里可同时转。
7. 检查器处理页点“重拓扑 · 5 积分”。**通过**：不弹批准；直接开始；完成后版本条出现 `3D v3`，连线写“重拓扑”；处理链状态显示“重拓扑 ✓”。
8. 点“绑骨”，再点“动画 · 待机”。**通过**：动画在绑骨完成前置灰；完成后各生成一个版本。
9. 在绑骨版本上打开格式页。**通过**：只列 FBX 和 GLB；FBX 行有单独下载。
10. 在 Meshy 原始模型上打开格式页。**通过**：glTF 标不可用并写原因；点“补齐格式 约 N 积分”不弹批准，直接开始；ZIP 下载成功，README 列出缺失格式。

### 5.4 场景四：2D↔3D 协作往返

1. 舞台在 3D v1，点“截图到 2D”。**通过**：0 积分；新版本 `2D v2` 来源写“3D v1 截图”；检查器显示真实截图尺寸。
2. 用画笔在胸口直接画，然后点“合并为新版本（0 积分）”。**通过**：出现 `2D v3 · 手绘`。
3. 在 2D v3 上点“用这张图换贴图”。**通过**：先选目标模型（默认 3D v1）；批准卡片写明“整套贴图重生，不能只改局部”，约 10 积分。
4. 不批准，继续发两条无关消息，等 130 秒后点批准。**通过**：若后端已持久化，正常提交；若未持久化，卡片在 120 秒时已变“已过期”，按钮是“重新发起”，点它重新冻结并提交。两种情况下都不得静默失败。
5. 挂着一张待批准卡片时，把顶栏模式切到自动。**通过**：弹二次确认；确认后那张卡片**仍然**待批准，没有被扣费。
6. 版本条点 2D v1，输入“换成绿色披风”。**通过**：舞台头提示“从旧版本继续”；新版本作为 2D v1 的分支显示，不接在最新版本后面。
7. 让 Meshy 账户余额低于 10（测试环境操作），再发起一次换贴图。**通过**：批准卡片上“批准”置灰并写余额；若强行提交后失败，失败卡片不出现“重试”和“换模型重试”，只出现“联系管理员”。
8. 舞台在 3D v1，输入框芯片显示 @model1。手打“用 @img6 去背景”。**通过**：芯片变灰并提示以 @img6 为准；Agent 回复写“基于 @img6”；去背景作用在 @img6 上。
9. 关掉浏览器，第二天打开。**通过**：会话列表有缩略图和时间；进入后舞台停在离开时的当前对象；全部产出按日期分组。
10. 找“交给同事”的入口。**通过**：界面上没有假的分享按钮；若已接入交接包，导出的 ZIP 含文件、提示词、来源链 README。

## 6. 验收跑 1 之后的取舍（10-08）

- 专注模式快捷键用 F，不用 Tab。原因：Tab 是键盘切换焦点的标准键，占用后键盘用户无法操作。§5 场景二第 2 步按 F 判定。
- 勾选"动画生成"时自动连带"骨骼绑定"，一次提交两步，按顺序执行。不再要求"绑骨完成前置灰"。原因：少一次等待和点击。处理链里两步分别显示状态。
- 修复轮 1 分三组并行：A 对话轮次、进度、失败提示、批准卡片；B 版本、来源连线、版本条；C 舞台、检查器、输入框标签（含 F36）、灯箱、比较、全部产出。说明见 `design/fix-round-1/common-brief.md`（项目共享文件夹，未入库）。
- 修复轮 1 的实现取舍（已接受）：
  - Tripo H3 的额外积分同意：在发送前于对话里出一张带勾选框的卡片，勾选后再发起请求。不放在批准卡片上，因为服务端在没有同意时根本不建批准卡片。
  - "用这张图换贴图"的目标模型：在舞台头按钮的弹出层里选，默认选这张图来源的模型，否则选最新的 3D。批准卡片只显示目标，不再改。
  - 批准卡片上"同时用另一个 3D 模型再生成"暂不做，列为后续项。
  - 任务运行中发消息：进入"排队中"，本轮结束后自动发出，可取消。队列只在当前页面有效，刷新后丢失。等批准时本轮立即结束，不再锁住输入框。
  - 切版本时未发送的蒙版：不弹确认，静默保留在原版本上，并提示"蒙版会保留在 …"，提示里可"放弃蒙版"。
